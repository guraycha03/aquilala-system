I want to implement a zero-cost "Phone Verification via Email Confirmation" user onboarding flow for our Aquilala Farm Supply Management System using Firebase Authentication and Firestore/MySQL. 

Please analyze my current codebase and build this feature step-by-step following these requirements:

### Architecture & Goal
1. We cannot use real Firebase SMS Phone Auth due to paid usage costs.
2. The primary user identity must still be their verified Phone Number (to ensure 1 phone number = 1 unique user account with no duplicates).
3. The Admin will pre-register farmers/users, which will trigger a FREE Email Link verification/activation flow.

### Implementation Checklist

1. **Admin Registration & Uniqueness Check (Backend/Firestore/MySQL)**
   - Create an Admin user creation function/route.
   - Before creating a user, query the database to verify if the submitted `phoneNumber` or `email` already exists.
   - If the phone number exists, return an error: "This phone number is already registered in the system."
   - If unique, save the user profile with `status: "pending_verification"` and generate an activation token.

2. **Free Activation Email Link (Firebase Auth / Nodemailer)**
   - Configure Firebase Passwordless Email Link Auth (`sendSignInLinkToEmail`) OR a custom email handler (using Nodemailer/Resend) to send a confirmation link to the user's email.
   - The email template must clearly state:
     > "You have been invited to join the Aquilala System with the registered phone number: [PHONE_NUMBER]. Click this link to confirm your phone number and activate your account."

3. **User Confirmation & Account Activation Page**
   - Create a frontend route/component (e.g., `/confirm-account`) that handles the landing from the email link.
   - Extract the token/email and target phone number from the parameters.
   - Prompt the user to set their password.
   - Upon form submission, update the user's status to `status: "active"`, complete their Firebase Authentication setup, and redirect them to the user dashboard.

### Code Expectations
- Clean, production-ready code with error handling for duplicate entries, expired tokens, and network failures.
- Provide step-by-step file edits or new files to create within our existing project structure.
