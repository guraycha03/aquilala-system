================================================================================
  AQUILALA FARM SUPPLY MANAGEMENT SYSTEM
  Full System Presentation Script — Page by Page
================================================================================

  Project: Aquilala Irrigators Association Inc. — Farm Supply Management System
  Location: Bulan, Sorsogon, Philippines
  Purpose: A three-sided marketplace platform connecting farmers, agricultural
           supply stores, and the association's administration.

  Roles:   Farmer | Store Owner | Admin
  Stack:   Laravel 11, PHP, Blade Templates, Chart.js, Leaflet/OpenStreetMap,
           OpenWeatherMap API, Groq Cloud AI (planned)

================================================================================


================================================================================
  PART 1 — AUTHENTICATION & LANDING
================================================================================

--- Welcome / Landing Page (/) ---

  This is the public-facing entry point. It displays the Laravel default
  landing page with navigation links to Log In and Register. It serves as
  the gateway before authentication.

--- Auth Layout ---

  Both Login and Signup share a split-screen layout:
    LEFT SIDE:  White card with the Aquilala logo, brand name "Aquilala
                Irrigators Association Inc.", and the form.
    RIGHT SIDE: Decorative panel with a farming background image, the
                Aquilala name, and the tagline:
                "Access recommended farm inputs, compare curated store
                offerings, and plan your costs with guided decision support."
  On mobile, only the form is shown.

--- Login Page (/login) ---

  Fields:
    - Email Address (required, validated on blur)
    - Password (required, min 8 characters, show/hide toggle)

  Both fields show real-time green/red feedback on blur. On success, the
  user is redirected to their role-appropriate dashboard. A link at the
  bottom reads: "Don't have an account yet? Register."

--- Signup Page (/register) ---

  Fields:
    - First Name (required, letters only)
    - Middle Initial (optional, max 2 characters)
    - Last Name (required, letters only)
    - Email Address (required, validated format)
    - Password (required, min 8 characters)
    - Confirm Password (must match)

  The role is automatically set to "farmer" — all public registrations
  create farmer accounts only. Store Owners and Admins are created
  internally. On success, the farmer is registered and redirected to
  their dashboard. A link at the bottom reads: "Already have an account?
  Log in."


================================================================================
  PART 2 — THE SIDEBAR (Shared Across All Roles)
================================================================================

  The sidebar is the main navigation shell visible on every page after
  login. Structure from top to bottom:

  1. BRAND SECTION
     - "Aquilala" title with green accent on "lala"
     - Subtitle: "Irrigators Association Inc."

  2. CLIMATE & WEATHER WIDGET (at top of nav)
     - Live clock updating every second (Philippine time, Asia/Manila)
     - Season indicator: blue circle for Wet Season, yellow for Dry Season
     - Current season label (e.g., "Wet Season")
     - Weather condition (e.g., "Rain Showers")
     - Current temperature (e.g., "24.5 C")
     - Season month range (e.g., "June - October")
     Data sources:
       - Season: SeasonHelper (hardcoded Philippine climate calendar)
       - Weather: OpenWeatherMap API for Bulan, Sorsogon (lat 12.67,
         lon 123.88), cached for 30 minutes. Falls back to
         season-aware defaults if no API key is configured.

  3. NAVIGATION MENU (role-based, different per user type)
     - Farmer sees 9 items under "FARMER HUB"
     - Store Owner sees 5 items under "MY STORE"
     - Admin sees 8 items under "ADMIN CONTROL"
     - Active link gets a visual hook connecting to the content area

  4. USER PROFILE FOOTER (bottom, dark green)
     - Avatar circle with user initials
     - User's full name
     - Role label (e.g., "Farmer", "Store Owner", "Admin")
     - Logout button (red-themed, POST to /logout)

  5. DESKTOP NOTIFICATION BELL (fixed top-right)
     - Bell icon that opens a dropdown panel
     - Currently shows "No new notifications" placeholder


================================================================================

================================================================================

  The farmer is the primary end-user. They are crop growers from the

    2. My Crops
    3. Recommendations
    4. Browse Products
    5. Request Quotation

--------------------------------------------------------------------------------
  FARMER PAGE 6: Request Quotation (/farmer/quotations/request)
--------------------------------------------------------------------------------

  The cost quotation generation form — the core DSS feature.

  TOP TO BOTTOM:

  1. PAGE HEADER
     - Title: "Generate a Cost Quotation"
     - Subtitle: "Get an instant farming cost breakdown — no approval
       needed. Store owners see this as demand intel."

  2. FORM CARD
     Header: "Farming Requirements"
     Green gradient progress bar

     Form Fields:
       a. Crop Type — searchable dropdown with all supported crops,
          supports custom entry
       b. Farming Season — two radio cards (Wet Jun-Jan / Dry Feb-May),
          auto-detected from current date
       c. Land Area (Hectares) — number input
       d. Select Products (Optional) — dynamic AJAX loader that fetches
          products matching crop+season; searchable with chips
       e. Additional Notes — optional textarea

     "Generate Cost Quotation" submit button

  3. INFO CARDS (3-column row)
     - How It Works: 5-step explanation of the quotation process
     - Supported Crops: description of crop coverage
     - Quotation Validity: "Valid for 14 days. Prices may change..."

  WHAT IT DOES: The farmer fills in their crop, season, and land area.
  The system's Decision Support Engine computes recommended product
  quantities using Decision Formulas (rate_per_hectare x land_area),
  adjusts for soil type and weather context, and generates a complete
  cost breakdown across all partner stores. The quotation is instant
  and requires no approval. Store owners see it as demand intelligence.

================================================================================
  PART 6 — SYSTEM ARCHITECTURE SUMMARY
================================================================================

  DATA FLOW — How the System Works End to End:

  1. A farmer registers via /register (role = "farmer" by default).
     They wait for admin approval.

  2. The admin reviews the application at /admin/approvals, verifies
     their documents, and approves or rejects.

  3. Once approved, the farmer logs in and sees their dashboard with
     season context, nearby stores, and workflow guide.

  4. The farmer registers their crops at /farmer/crops — setting crop
     type, land area, planting date, and season. The system tracks
     growth stages from Land Prep through Harvest.

  5. The farmer goes to /farmer/recommendations to see smart product
     suggestions matched to their crops and the current season.

  6. The farmer browses the marketplace at /farmer/products/browse,
     filters by season, searches by name, and clicks into product
     details.

  7. The farmer generates a cost quotation at /farmer/quotations/request
     — selecting crop, season, and land area. The DSS engine uses
     Decision Formulas (rate_per_hectare x land_area) to compute
     recommended quantities and generates a complete cost breakdown
     across all partner stores. This is instant — no approval needed.

  8. The store owner sees the quotation as "demand intelligence" at
     /store/quotations — they can view which farmers are exploring
     their products and what quantities they need, but they cannot
     modify the quotation.

  9. The store owner manages their product catalog at /store/storefront,
     monitors stock at /store/inventory, and defines application rates
     (formulas) at /store/formulas that power the DSS engine.

  10. The admin monitors everything from /admin/dashboard — user
      growth, marketplace health, quotation activity — with deep
      analytics at /admin/analytics and a full audit trail at
      /admin/audit.

  KEY DESIGN PRINCIPLES:
    - Farmers generate quotations independently (no approval flow)
    - Store owners get read-only demand visibility (not transactional)
    - Admins oversee the platform (users, approvals, analytics)
    - The Decision Support Engine is rule-based (formulas) with
      planned AI enhancement (Groq Cloud)
    - All data is localized to Bulan, Sorsogon barangays
    - Season-aware: the system adapts recommendations, products, and
      weather context based on the Philippine farming calendar

  BARANGAYS SERVED:
    Inararan, J.P. Laurel, Aquino, Somagongsong, A. Bonifacio,
    Managanaga — all within Bulan, Sorsogon, Philippines.

  WEATHER DATA:
    OpenWeatherMap API (One Call 3.0) for Bulan, Sorsogon
    Coordinates: 12.6700 N, 123.8800 E
    Cached for 30 minutes. Falls back to season-aware deterministic
    defaults when API key is not configured.

  SEASON CALENDAR:
    Wet Season: June - January (Tag-ulan)
    Dry Season: February - May (Tag-init)
